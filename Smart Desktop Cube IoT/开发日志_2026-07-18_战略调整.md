## 关键技术挑战：Yeelight 灯带控制

### 问题描述
项目原计划通过 Yeelight LAN Control Protocol（TCP 55443）控制灯带，实现灯光亮度、色温调节。但遇到以下问题：

1. **米家定制版灯带移除了 LAN 控制开关**
   - 用户购买的"米牌"Yeelight 1S 灯带是米家定制版
   - 该版本在固件层面禁用了局域网控制功能
   - Yeelight App 中的"LAN 控制"开关不存在

2. **手机热点客户端隔离**
   - ESP32 和灯带都连接到手机热点
   - 手机热点启用了 AP 隔离（Client Isolation）
   - 导致 ESP32 无法与灯带进行 TCP/UDP 通信
   - 诊断结果：miio UDP 54321 无响应，TCP 55443 返回 "Connection reset by peer"

3. **Windows 移动热点无法使用**
   - 尝试使用 Windows 自带移动热点替代手机热点
   - ESP32 无法连接到 Windows 热点（可能是驱动或 5GHz 频段问题）

### 尝试的解决方案

#### 方案 1：SSDP 发现 + TCP 直连
- 实现 SSDP 多播搜索（239.255.255.250:1982）
- 实现 TCP 55443 JSON-RPC 通信
- 实现两层重连逻辑（指数退避搜索 + 固定间隔 TCP 重连）
- **结果**：被手机热点客户端隔离阻断

#### 方案 2：ESP32 AP+STA 双模
- ESP32 自建 WiFi AP（SSID: CubeLight, 密码: cube2026）
- 灯带连接到 ESP32 的 AP（192.168.4.x 网段，无隔离）
- ESP32 同时作为 STA 连接手机热点（上 MQTT）
- **结果**：灯带配对失败（米家 App 要求设备联网验证，但 CubeLight AP 无公网）

#### 方案 3：python-miio 协议直接控制
- 使用 miio 协议（UDP 54321）绕过 Yeelight LAN 控制开关
- 需要提取设备 32 位 Token
- **结果**：复杂度过高，时间不足，放弃

### 结论
受限于硬件厂商策略（米家定制版移除 LAN 控制）和网络环境（手机热点隔离），灯带控制功能无法实现。作为未来扩展功能，可在以下条件下实现：
- 购买路由器（避免热点隔离）
- 更换灯带型号（选择支持 LAN 控制的版本）
- 使用 WS2812B LED 灯带（ESP32 GPIO 直接控制，无厂商依赖）

## 战略调整：从"数据看板"到"智能终端"

### 问题诊断
当前项目功能组合：
```
传感器 → 上传数据 → 第三方 App 显示 → 网页显示 → 调 AI API 分析
```

**问题**：
1. 依赖第三方 App（点灯科技 Blinker），技术含量低
2. AI 只是"调 API 分析当前数据"，没有深度
3. ESP32 只是"数据中转站"，没有本地智能
4. 整体看起来像"数据看板"，缺乏竞争力

**评委视角**：
- 这类项目在比赛中很常见，大多数学生都做"数据上传 + App 显示"
- 没有突出亮点，容易被淹没在同类项目中
- 预估分数：82-85 分（Good 级别，但不突出）

### 新战略方向
**目标**：从"数据看板"升级为"智能终端"

**核心思路**：
```
ESP32 本地智能决策 + 历史数据趋势 + 自定义 Web 控制
```

**预期效果**：
- 分数提升：82-85 → 88-92 分
- 竞争力：从"普通项目"变为"优秀项目"
- 技术深度：展示边缘计算、趋势预测、智能场景联动

## 新增功能规划

### 功能 1：本地智能决策（优先级：高，耗时：1-2 小时）

**目标**：ESP32 不只是上传数据，而是在本地做决策

**实现内容**：

1. **自动屏幕亮度调节**
   ```cpp
   // 根据 BH1750 光照强度自动调节屏幕亮度
   if (sensorData.light < 100) {
       status.screen_brightness = 80;   // 暗环境降低亮度
   } else if (sensorData.light > 500) {
       status.screen_brightness = 255;  // 亮环境提高亮度
   }
   ```

2. **空气质量告警**
   ```cpp
   // CO2 > 1000ppm 或 TVOC > 0.5mg/m³ 时告警
   if (sensorData.eco2 > 1000 || sensorData.tvoc > 0.5) {
       status.air_quality_alert = true;
       // UI 弹窗："空气质量差，建议开窗通风"
   }
   ```

3. **温度舒适度判断**
   ```cpp
   // 温度 < 18°C 或 > 28°C 时告警
   if (sensorData.temp < 18 || sensorData.temp > 28) {
       status.temp_comfort_alert = true;
   }
   ```

4. **专注模式自动进入**
   ```cpp
   // 雷达检测到人 > 5 分钟，自动进入专注模式
   if (sensorData.human_duration > 300 && !status.focus_mode) {
       status.focus_mode = true;
       status.request_focus_screen = true;
   }
   ```

**技术亮点**：
- 展示"边缘智能"概念（Edge Intelligence）
- ESP32 不只是数据中转，而是在做决策
- 符合 IoT 发展趋势（从云端智能到边缘智能）

**代码位置**：
- 新建 `src/LocalIntelligence.cpp`
- 在 `main.cpp` 中创建 FreeRTOS 任务，每 5 秒检查一次

### 功能 2：历史数据记录 + 趋势图（优先级：高，耗时：2-3 小时）

**目标**：展示数据趋势，实现"预测"而非单纯"分析"

**实现内容**：

1. **历史数据记录**
   ```cpp
   // 在 DataPool.h 中定义
   #define HISTORY_SIZE 60  // 记录最近 60 个数据点（5 分钟间隔 = 5 小时）
   
   typedef struct {
       float temp[HISTORY_SIZE];
       float humi[HISTORY_SIZE];
       float light[HISTORY_SIZE];
       float eco2[HISTORY_SIZE];
       int history_index;
       int history_count;
   } SensorHistory;
   
   extern SensorHistory sensorHistory;
   ```

2. **定时记录**
   ```cpp
   // 每 5 分钟记录一次
   void recordHistory() {
       sensorHistory.temp[sensorHistory.history_index] = sensorData.temp;
       sensorHistory.humi[sensorHistory.history_index] = sensorData.humi;
       sensorHistory.light[sensorHistory.history_index] = sensorData.light;
       sensorHistory.eco2[sensorHistory.history_index] = sensorData.eco2;
       
       sensorHistory.history_index = (sensorHistory.history_index + 1) % HISTORY_SIZE;
       if (sensorHistory.history_count < HISTORY_SIZE) {
           sensorHistory.history_count++;
       }
   }
   ```

3. **TFT 趋势图显示**
   ```cpp
   // 使用 LVGL chart 控件显示历史趋势
   lv_obj_t * chart = lv_chart_create(lv_scr_act());
   lv_chart_set_type(chart, LV_CHART_TYPE_LINE);
   lv_chart_set_point_count(chart, sensorHistory.history_count);
   
   // 添加温度数据系列（红色）
   lv_chart_series_t * temp_series = lv_chart_add_series(
       chart, lv_palette_main(LV_PALETTE_RED), LV_CHART_AXIS_PRIMARY_Y);
   
   // 填充历史数据
   for (int i = 0; i < sensorHistory.history_count; i++) {
       int idx = (sensorHistory.history_index - sensorHistory.history_count + i + HISTORY_SIZE) % HISTORY_SIZE;
       lv_chart_set_next_value(chart, temp_series, sensorHistory.temp[idx] * 10);
   }
   ```

**技术亮点**：
- 展示"趋势预测"能力（基于历史数据）
- 比单纯显示当前值更有深度
- LVGL chart 控件使用（展示 UI 设计能力）

**代码位置**：
- 在 `DataPool.h` 中添加 `SensorHistory` 结构体
- 在 `Task_Sensors.cpp` 中每 5 分钟调用 `recordHistory()`
- 在 UI 中添加新页面显示趋势图

### 功能 3：自定义 Web 控制（优先级：中，耗时：3-4 小时）

**目标**：摆脱第三方 App 依赖，展示全栈能力

**实现内容**：

1. **ESP32 Web 服务器**
   ```cpp
   #include <WebServer.h>
   
   WebServer server(80);
   
   void handleRoot() {
       String html = "<html><body>";
       html += "<h1>Smart Desktop Cube</h1>";
       html += "<p>温度: " + String(sensorData.temp) + "°C</p>";
       html += "<p>湿度: " + String(sensorData.humi) + "%</p>";
       html += "<p>光照: " + String(sensorData.light) + " lux</p>";
       html += "<button onclick=\"fetch('/toggle_focus')\">切换专注模式</button>";
       html += "</body></html>";
       server.send(200, "text/html", html);
   }
   
   void handleToggleFocus() {
       status.focus_mode = !status.focus_mode;
       server.send(200, "text/plain", "OK");
   }
   
   void setup() {
       server.on("/", handleRoot);
       server.on("/toggle_focus", handleToggleFocus);
       server.begin();
   }
   ```

2. **API 接口**
   - `GET /` - 主页，显示传感器数据
   - `GET /api/data` - JSON 格式传感器数据
   - `POST /api/control` - 控制指令（专注模式、设备锁等）
   - `GET /api/history` - 历史数据（用于网页端趋势图）

**技术亮点**：
- 摆脱第三方 App 依赖（点灯科技 Blinker）
- 展示全栈能力（ESP32 后端 + 网页前端）
- 符合 IoT 架构（设备提供 API，前端调用）

**代码位置**：
- 新建 `src/WebServer.cpp`
- 在 `main.cpp` 中初始化 Web 服务器
- 网页端（已有网站）调用 ESP32 的 API
