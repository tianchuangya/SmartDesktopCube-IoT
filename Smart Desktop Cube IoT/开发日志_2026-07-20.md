## 二、OTA进度条修复（核心Bug）

### 问题描述

OTA任务运行在 Core 1，直接调用 LVGL 函数（`otaScreenShow` / `otaScreenUpdateProgress`）。但 LVGL 不是线程安全的，只能从 LVGL 定时器任务（LVGL timer task）中调用。导致进度条虽然代码写了，但根本渲染不出来。

### 修复方案

| 文件 | 修改内容 |
|------|----------|
| `OTAManager.cpp` | OTA任务不再调用任何LVGL函数，改为只更新共享字段：`status.ota_in_progress` / `ota_progress` / `ota_status_text` |
| `custom.c` | LVGL定时器每帧检查 `status.ota_in_progress`，在正确的线程上下文中调用 `otaScreenShow()` / `otaScreenUpdateProgress()` 渲染进度 |
| `OTAManager.cpp` | 移除对 `OTAScreen.h` 的依赖 |

### 核心原则

> LVGL 函数只能从 LVGL 定时器任务调用，其他任务通过共享状态通信。

## 三、OTA期间任务暂停机制

OTA下载/写入Flash期间，暂停其他任务以保证系统稳定性和带宽：

| 任务 | 文件 | 暂停方式 |
|------|------|----------|
| 雷达 + 专注模式状态机 | `Task_Control.cpp` | 200ms sleep 循环 |
| 传感器采集 | `Task_DataRead` | 500ms sleep 循环 |
| 数据上报 / Blinker推送 / 心跳 | `MqttReconnectTask.cpp` | 跳过执行，但保持MQTT连接（用于OTA状态上报） |
| 自动亮度 / 告警 / 历史数据 | `LocalIntelligence.cpp` | 1000ms sleep 循环 |

```

  ├── code: 200 → 有新版本，网页显示版本信息
```

## 七、启动流程重构（黑色背景 + 模块加载）

### 7.1 需求

- 启动画面背景改为纯黑色
- 启动期间加载所有传感器模块，每个模块5次重试
- 模块加载期间持续显示启动画面（小眠图片 + 状态文字）
- 所有模块加载完成后自动过渡到主界面

### 7.2 实现方案：两阶段初始化

| 阶段 | 函数 | 内容 | 耗时 |
|------|------|------|------|
| Phase 1 | `Device_InitDisplay()` | Serial + LVGL + 触摸 + UI setup | ~1s |
| Phase 2 | `Device_InitModules()` | BH1750 → AHT20 → ENS160 → Radar（各5次重试） | 2~12s |

### 7.3 启动时序

```
setup()
  ├── Device_InitDisplay()     ← 快速，启动画面立即渲染
  ├── Task_LVGL_Init()         ← LVGL任务启动，定时器开始轮询
  ├── Task_ModuleLoader        ← 后台任务调用 Device_InitModules()
  │     ├── BH1750 (5 retries)
  │     ├── AHT20  (5 retries)
  │     ├── ENS160 (5 retries)
  │     └── Radar  (5 retries)
  │     └── status.modules_ready = true
  └── 其他任务（网络/MQTT/OTA/Web）

LVGL定时器 (500ms):
  boot_to_main_cb() → 检查 status.modules_ready → 切换到 mainScreen
```

### 7.4 修改文件

| `src/main.cpp` | 先InitDisplay→启动LVGL→创建ModuleLoader任务→再初始化网络 |
