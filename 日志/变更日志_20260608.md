# Smart Desktop Cube IoT — 变更日志 2025-06-08

## 一、变更概述

本次改动围绕四个主线：
1. **BLE 蓝牙连接失败 UI 反馈** — 连接失败/未连接时弹 Toast 提示 + 状态标签实时显示
2. **专注模式冷却机制** — 手动退出后 30s 冷却期，防止死循环；限制只在主屏自动进入
3. **编译错误修复** — NimBLE 构造函数、头文件路径、字段重命名遗漏
4. **UI 交互优化** — WiFi 图标触摸面积加大、中文缺字临时改用英文

## 二、新增功能

### 2.1 BLE 连接状态 UI 反馈

**功能**：进入 settingsScreen 后，底部显示 BLE 连接状态标签（绿=已连接 / 红=未连接）。滑动滑块或切换开关时若 BLE 未连接，弹出红色半透明 Toast 提示，3.5 秒自动消失。开关在未连接时自动弹回原位。

**涉及文件**：
| 文件 | 修改内容 |
|------|---------|
| `src/BluetoothLight.h` | ⭐ 新增 `connection_attempts`、`last_fail_time`、`last_connect_failed` 字段；新增 `BL_ConsumeConnectFailedFlag()`、`BL_GetStatusMsg()` 函数声明 |
| `src/BluetoothLight.cpp` | ⭐ `BL_DoConnect()` 失败时标记 `last_connect_failed = true`、递增 `connection_attempts`；成功时清零。实现 `BL_ConsumeConnectFailedFlag()`（消费标记）和 `BL_GetStatusMsg()`（返回状态字符串）。`BL_SetLight()` 未连接时输出串口警告 |
| `src/ui/generated/gui_guider.h` | 新增 `settingsScreen_label_ble_status` 标签声明 |
| `src/ui/generated/setup_scr_settingsScreen.c` | 底部新增 BLE 状态标签（y=222），默认文字 "BLE: checking..." |
| `src/ui/generated/events_init.c` | ⭐ **Toast 弹窗系统**：`show_toast()` 创建浮层 + `lv_timer_create` 3.5s 自动删除。**BLE 状态刷新**：进入 settingsScreen 启动 1s 周期定时器刷新状态标签和消费连接失败标记。**滑块/开关事件**：先更新 UI 标签，再 `check_ble_or_toast()` 判断——未连接则弹红色 Toast，开关额外弹回原位 |

### 2.2 专注模式冷却机制（防死循环）

**问题**：用户手动退出专注模式后，雷达仍检测到人，`focusMode_update()` 下一周期立即再次自动进入，形成死循环。

**解决方案**：引入"失焦冷却时间"——手动退出后 30 秒内禁止自动进入。用户主动进入则取消冷却。

**涉及文件**：
| 文件 | 修改内容 |
|------|---------|
| `src/DataPool.h` | ⭐ `FocusConfig_t` 新增 `focus_cooldown_ms`（默认 30000）、`last_manual_exit_ms`（默认 0）。`DeviceStatus` 新增 `on_main_screen` |
| `src/DataPool.cpp` | 新字段初始化 |
| `src/focus_mode.h` | ⭐ 新增 `focusMode_notifyManualExit()` 函数声明；添加 `extern "C"` 包裹 |
| `src/focus_mode.cpp` | ⭐ **auto-enter 条件增加**：`!in_cooldown`（冷却期内禁止）+ `status.on_main_screen`（仅主屏允许）。**新增函数** `focusMode_notifyManualExit()`：记录退出时间戳 → 启动冷却 → 重置 presence 累积时间 → 恢复白光 |
| `src/ui/custom/custom.c` | 手动退出时调用 `focusMode_notifyManualExit()` + `sensorData.focus_duration = 0`（补漏）。手动进入时 `last_manual_exit_ms = 0` 取消冷却。每帧更新 `status.on_main_screen` |

### 2.3 Toast 弹窗通用组件

**位置**：`src/ui/generated/events_init.c`

- `show_toast(msg, bg_color)` — 创建半透明浮层弹窗，居中显示，3.5 秒后自动删除
- `show_ble_disconnected_toast()` — BLE 未连接专用红色弹窗
- `check_ble_or_toast()` — 便捷函数：检查 BLE 连接，未连接则弹 Toast 返回 false

### 4.2 设置屏幕中文缺字

**问题**：`lv_font_yezi_hei_16` 字体文件不含"亮""度""色""温"等汉字，导致显示方框。

> **根因**：GUI Guider 导出字体时只包含设计界面中已使用字符的字形。settingsScreen 的这几个标签文字使用的字符未在导出范围内。

**临时方案**：涉及缺字的标签改用英文

| 标签 | 修改前 | 修改后 | 状态 |
|------|--------|--------|------|
| label_1 | 亮度： | Light | ✅ 可显示 |
| label_2 | 色温: | Temp | ✅ 可显示 |
| label_4 | 台灯设置 | 台灯设置 | ✅ 原本就正常（yezi_hei_20 含这些字） |
| btn_1 | 返回 | 返回 | ✅ 原本就正常（yezi_hei_16 含"返""回"） |
| BLE 状态 | 蓝牙: xxx | BLE: xxx | ✅ 可显示 |
| Toast | 蓝牙未连接... | BLE not connected... | ✅ 可显示 |

**彻底修复**：需在 GUI Guider 中重新配置 yezi_hei_16 和 yezi_hei_12 字体，添加缺失字符：
- yezi_hei_16 补充：亮(U+4EAE)、度(U+5EA6)、色(U+8272)、温(U+6E29)、：(U+FF1A)
- yezi_hei_12 补充：蓝(U+84DD)、牙(U+7259)、检(U+68C0)、测(U+6D4B)、已(U+5DF2)、连(U+8FDE)、接(U+63A5)、未(U+672A)

## 五、关键逻辑流程图

### 5.1 专注模式自动进入决策链（focusMode_update）

```
雷达检测每 50ms 一次
  │
  ├─ status.is_human_exist == true ?
  │   ├─ 上升沿 → 记录 firstPresenceTime
  │   └─ 持续有人 > auto_enter_delay_ms (5s) ?
  │       ├─ 是 → 检查条件：ALL_TRUE(
  │       │     radar_ok,
  │       │     auto_enter_enabled,
  │       │     status.on_main_screen,          ← ⭐ 新增：必须主屏
  │       │     !status.focus_mode,
  │       │     !in_cooldown,                    ← ⭐ 新增：不在冷却期
  │       │   )
  │       │   ├─ 全部满足 → 进入专注模式 + 暖光 + 切屏
  │       │   └─ 不满足 → 跳过
  │       └─ 否 → 继续累积
  │
  └─ status.is_human_exist == false ?
      └─ 下降沿 → 重置 firstPresenceTime
```

### 5.2 手动退出冷却机制

```
用户切离 fouseScreen
  │
  └─ custom.c 检测 active ≠ fouseScreen
      │
      └─ focusMode_notifyManualExit()
          ├─ last_manual_exit_ms = millis()    ← 启动冷却计时
          ├─ firstPresenceTime = 0              ← 清空累积
          ├─ BL_PresetWhite()                   ← 恢复白光
          └─ 30s 内 in_cooldown = true → auto-enter 被阻止
              ├─ 30s 后冷却过期 → auto-enter 恢复
              └─ 用户主动点 logo 进专注 → 取消冷却（last_manual_exit_ms = 0）
```

### 5.3 BLE 连接状态流转

```
BL_Task (200ms 周期, 核心1)
  │
  ├─ 未连接 → BL_DoConnect() 每 5s 重试
  │   ├─ 失败 → last_connect_failed = true → connection_attempts++
  │   └─ 成功 → connected = true → connection_attempts = 0
  │
  └─ 已连接 → 检查 pending_update → 发送 BLE 指令
      └─ 发送失败 → BL_DoDisconnect() → connected = false

UI 层 (LVGL 任务, 核心1)
  │
  ├─ 进入 settingsScreen → 启动 1s 定时器
  │   ├─ 读 BL_GetStatusMsg() → 更新标签颜色/文字
  │   └─ 读 BL_ConsumeConnectFailedFlag() → 消费失败标记 → 弹 Toast
  │
  └─ 滑块/开关操作 → check_ble_or_toast()
      ├─ 已连接 → 发送 BLE 指令
      └─ 未连接 → 弹红色 Toast + 开关弹回
```
