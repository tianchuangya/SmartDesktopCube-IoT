# Smart Desktop Cube IoT — 变更日志 2025-06-09

## 一、变更概述

本次改动围绕一条主线：**BLE 灯光控制架构重构** — 放弃小米蓝牙 Mesh 协议，改为自建 BLE GATT 双色温灯光控制系统。

核心问题：原方案目标是小米生态的"山晶特控 氛围夜灯 Mesh Q1"，该设备使用蓝牙 SIG Mesh 协议，需要配网密钥（NetKey/AppKey/DeviceKey）才能发送控制指令。普通 BLE GATT 直连无法与 Mesh 设备通信。密钥存储在米家云端和手机 APP 数据库中，第三方无法合法获取。

解决方案：自建 BLE 灯光控制链路——
- ESP32-S3（主控）→ BLE Client → 自动扫描连接
- ESP32-S3（灯控）→ BLE GATT Server → 双路 PWM 驱动暖白/冷白 LED 灯带
- 全自主设计的 GATT 服务和通信协议

## 四、BLE 协议变更详情

### 4.1 原协议（已废弃）

| 项目 | 值 |
|------|-----|
| 目标设备 | 小米蓝牙 Mesh 灯（山晶特控 Mesh Q1） |
| 协议类型 | SIG Bluetooth Mesh（加密） |
| 连接方式 | 硬编码 MAC 地址直连 |
| Service UUID | `00000100-0065-6c62-2e74-6f696d2e696d` |
| 数据格式 | `[brightness, color_temp]` 2字节写入单个特征 |
| 废弃原因 | 需要 Mesh 配网密钥，无法合法获取 |

### 4.2 新协议（当前）

| 项目 | 值 |
|------|-----|
| 目标设备 | 自建 ESP32-S3/C3 灯光控制器 |
| 协议类型 | 标准 BLE GATT（明文） |
| 连接方式 | 按设备名 `SmartCube-Light` 自动扫描发现 |
| Service UUID | `12345678-1234-1234-1234-123456789abc` |
| 亮度特征 UUID | `12345678-1234-1234-1234-123456789abd`（1 字节，0-100） |
| 色温特征 UUID | `12345678-1234-1234-1234-123456789abe`（1 字节，0-100） |
| 数据格式 | 两个独立特征，各写入 1 字节 |

## 五、系统架构变更

### 5.1 原架构（失败）

```
ESP32-S3                 小米 Mesh 灯
BLE Client ────❌──── BLE Mesh (加密)
                     需要：NetKey + AppKey + DeviceKey
                     无法获取 → 永远连不上
```

### 5.2 新架构（当前）

```
┌──────────────────────┐        BLE GATT        ┌──────────────────────┐
│  ESP32-S3（主控）      │ ◄──────────────────► │  ESP32-S3（灯控）      │
│                      │   自动扫描 & 连接       │                      │
│  BluetoothLight.cpp  │   亮度: 0-100 (1字节)  │  BLE GATT Server     │
│  扫描 "SmartCube-Light"│  色温: 0-100 (1字节)  │  GPIO5 → PWM 暖白     │
│  自动连接 & 重连       │                       │  GPIO6 → PWM 冷白     │
│                      │                       │  MOS管 → LED灯带      │
└──────────────────────┘                       └──────────────────────┘
```

## 六、灯光控制器固件（ESP32-S3 灯控端）

### 6.1 硬件需求

| 物料 | 用途 | 价格 |
|------|------|------|
| ESP32-S3/C3 开发板 | 运行 BLE Server + PWM 控制 | 已有备件 |
| IRF520 双路 MOS 管模块 | 弱电转强电，驱动 LED 灯带 | ¥5-8 |
| COB 双色温灯带 (5V USB) | 暖白 + 冷白 LED 光源 | ¥5-10 |

### 6.2 BLE GATT 服务设计

```
Service: 12345678-1234-1234-1234-123456789abc
├── Characteristic: 12345678-...789abd (亮度)
│   ├── READ:  返回当前亮度值 (1 字节)
│   ├── WRITE: 设置亮度 0-100
│   └── 写入后自动更新 PWM 输出
│
└── Characteristic: 12345678-...789abe (色温)
    ├── READ:  返回当前色温值 (1 字节)
    ├── WRITE: 设置色温 0-100 (0=暖2700K, 50=中4500K, 100=冷6500K)
    └── 写入后自动重新计算暖白/冷白 PWM 比例
```

### 6.3 PWM 混色算法

```
warmRatio = (100 - colorTemp) / 100
coldRatio = colorTemp / 100
warmPWM = brightness × warmRatio × 255 / 100
coldPWM = brightness × coldRatio × 255 / 100
```

### 6.4 引脚定义

| 引脚 | 功能 | 连接 |
|------|------|------|
| GPIO5 | 暖白 PWM | MOS管模块 IN1 → LED灯带暖白 |
| GPIO6 | 冷白 PWM | MOS管模块 IN2 → LED灯带冷白 |
| GND | 共地 | MOS管模块 GND |

## 九、技术亮点（答辩用）

1. **协议选型决策**：调研了小米 Bluetooth Mesh → 标准 BLE GATT 两条路径，分析了加密要求、密钥获取可行性、实现复杂度，最终选择自建 GATT 方案
2. **自动扫描发现**：无需硬编码 MAC 地址，按设备名自动搜索，容错性强
3. **独立特征设计**：亮度和色温分开两个 GATT Characteristic，符合蓝牙标准规范
4. **PWM 双路混色**：通过调整暖白/冷白比例实现无极色温调节，而非简单的 RGB 混色
5. **全链路自主**：从 BLE 协议设计、固件编写、PWM 驱动到 UI 交互，全自研
